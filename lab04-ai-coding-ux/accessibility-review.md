การตรวจประเมินความสอดคล้องตามมาตรฐาน **WCAG 2.1 ระดับ AA** บนแบบร่าง UI Mockup ของระบบคลังสินค้า (Smart Inventory Management)

## 1. ตารางตรวจ Accessibility Checklist

| รายการตรวจ | ผ่าน หรือ ไม่ผ่าน | สิ่งที่ตรวจพบ / สิ่งที่แก้ไข |
| :--- | :---: | :--- |
| **1. ข้อความหลักสี #111827 บนพื้นขาว contrast อย่างน้อย 4.5 ต่อ 1** | **ผ่าน** | ข้อความเนื้อหาหลัก (Body Text) ใช้รหัสสี `#111827` บนพื้นหลัง `#FFFFFF` มีค่า Contrast Ratio เท่ากับ **16.1:1** ซึ่งสูงกว่าเกณฑ์ขั้นต่ำ 4.5:1 ตาม WCAG AA มาก |
| **2. ปุ่ม Primary มี contrast เพียงพอ** | **ผ่าน** | ปุ่มหลักใช้สี `#1E40AF` (น้ำเงินเข้ม) คู่กับตัวอักษรสีขาว `#FFFFFF` มี Contrast Ratio เท่ากับ **8.5:1** (ผ่านเกณฑ์ WCAG AA สำหรับ Graphical Object & Text ที่ต้องไม่ต่ำกว่า 3:1 และ 4.5:1) |
| **3. ทุกช่องกรอกมี label ที่มองเห็น** | **ผ่าน** | ทุก Input Field มีแท็ก `<label>` ข้อความชัดเจนวางอยู่เหนือช่องกรอกเสมอ และคงอยู่ตลอดเวลาแม้ผู้ใช้จะเริ่มพิมพ์ข้อความแล้วก็ตาม |
| **4. ช่องที่บังคับกรอกมีสัญลักษณ์ชัด** | **ผ่าน** | กำกับด้วยเครื่องหมายดอกจันสีแดง `*` และระบุคำว่า "(บังคับกรอก)" ใน `aria-label` เพื่อให้ Screen Reader อ่านออกเสียงได้ถูกต้อง |
| **5. error ไม่ได้ใช้สีอย่างเดียว มีไอคอนและข้อความด้วย** | **ผ่าน** | เมื่อเกิด Validation Error แสดงไอคอนเตือน `[!]` ร่วมกับข้อความอธิบายวิธีแก้ปัญหา (เช่น "กรุณากรอกราคาเป็นตัวเลขที่มากกว่า 0") ไม่พึ่งพาการเปลี่ยนสีกรอบเป็นสีแดงเพียงอย่างเดียว |
| **6. ลำดับการกด Tab เรียงบนลงล่าง ซ้ายไปขวา** | **ผ่าน** | จัดเรียง `tabindex` ตามลำดับสายตา (Visual DOM Order) จากบนลงล่าง: เริ่มจาก ประเภทสินค้า -> ชื่อสินค้า -> รหัส SKU -> หมวดหมู่ -> ราคา -> จำนวน -> ปุ่มยกเลิก -> ปุ่มบันทึก |
| **7. ปุ่มมีชื่อบอกหน้าที่ชัด ไม่ใช่ OK หรือกากบาท** | **ผ่าน** | ใช้ข้อความระบุการกระทำชัดเจน ได้แก่ "บันทึกสินค้าใหม่ (Save)", "ยกเลิก (Cancel)", "เข้าสู่ระบบ (Login)" ไม่ใช้คำกำกวมอย่าง "OK" หรือไอคอน "X" โดด ๆ |

## 2. จุดที่ AI พลาด และการแก้ไขโดยนักศึกษา (ระบุ 2 จุดตามเกณฑ์ Rubric)

### จุดที่ 1: AI พลาดโดยใช้ Placeholder แทน Label ถาวรในแบบฟอร์ม Add Product
- **สิ่งที่ AI สร้างให้ครั้งแรก (ปัญหา)**:
  AI ร่างโค้ดฟอร์มโดยใส่เพียง `<input placeholder="กรอกชื่อสินค้า*">` โดยไม่มีองค์ประกอบ `<label>` อยู่ภายนอก
  ```html
  <!-- โค้ดที่ AI ส่งมาในรอบแรก (ผิด Accessibility) -->
  <input type="text" placeholder="ชื่อสินค้า*" name="product_name" />
  <input type="number" placeholder="ราคาขาย*" name="price" />
  ```
- **ผลกระทบ**:
  เมื่อพนักงานเริ่มพิมพ์ตัวอักษรแรก ข้อความ placeholder จะหายไปทันที หากพนักงานถูกขัดจังหวะหรือหันไปเช็กสินค้าจริง จะจำไม่ได้ว่าช่องที่กำลังกรอกอยู่คือราคาหรือจำนวนสินค้า นอกจากนี้เครื่องอ่านหน้าจอ (Screen Reader) อาจข้ามฟิลด์นี้ไปเพราะไม่มี accessible name
- **การแก้ไขด้วยตนเอง**:
  เพิ่ม `<label>` ถาวรวางตำแหน่งไว้ด้านบนของทุก Input Box พร้อมเชื่อมโยง `for` attribute เข้ากับ `id` ของ input อย่างถูกต้อง:
  ```html
  <!-- โค้ดที่แก้ไขแล้ว (ถูกต้องตามหลัก Accessibility) -->
  <label for="product-name" class="form-label">
    ชื่อสินค้า (Product Name) <span class="required" aria-hidden="true">*</span>
  </label>
  <input id="product-name" type="text" aria-required="true" class="form-input" />
  ```

### จุดที่ 2: AI ลืม Error State ที่เข้าถึงได้ และแจ้งเตือนด้วยสีแดงเพียงอย่างเดียวโดยไม่มีคำแนะนำวิธีแก้
- **สิ่งที่ AI สร้างให้ครั้งแรก (ปัญหา)**:
  เมื่อเกิดข้อผิดพลาดในการกรอกราคาหรือสต็อก AI เปลี่ยนเพียงเส้นขอบกล่องข้อความเป็นสีแดง (`border: 1px solid red;`) และแสดงข้อความสั้น ๆ ด้านล่างว่า `"Invalid Input"`
  ```text
  [กรอบสีแดง] [           ]
  Invalid Input
  ```
- **ผลกระทบ**:
  ผู้ใช้ที่มีภาวะตาบอดสีแดง-เขียว (Protanopia / Deuteranopia) จะมองไม่เห็นความแตกต่างของเส้นขอบสีแดง และข้อความ `"Invalid Input"` ไม่ได้ช่วยให้ผู้ใช้ที่มีทักษะเทคโนโลยีระดับต่ำเข้าใจได้เลยว่าตนเองกรอกผิดตรงไหนและต้องแก้ไขอย่างไร
- **การแก้ไขด้วยตนเอง**:
  1. เพิ่มไอคอนเตือน `[!]` (Warning Icon) นำหน้าข้อความ error เสมอ
  2. เปลี่ยนข้อความ error ให้บอกวิธีการแก้ไขที่ชัดเจน (Actionable Guidance) เช่น:
     `[!] ข้อผิดพลาด: กรุณากรอกราคาขายเป็นตัวเลขจำนวนเต็มหรือทศนิยมที่มากกว่า 0 บาท`
  3. เพิ่ม `aria-describedby` และ `role="alert"` เพื่อให้ผู้พิการทางสายตาได้รับการแจ้งเตือนทันทีที่มี error เกิดขึ้น
